# C4 Architecture Diagrams

## Level 1 — System Context

Who interacts with the Car Repair Shop system and what external systems are involved.

```mermaid
flowchart TD
    customer["Customer\n[Person]\nOwns the vehicle;\napproves or rejects the budget"]
    attendant["Attendant\n[Person]\nRegisters OSs and records delivery"]
    mechanic["Mechanic\n[Person]\nPerforms diagnosis and execution"]
    admin["Admin\n[Person]\nManages catalogue, users, and stock"]

    system["Car Repair Shop API\n[Software System]\nManages service orders, stock,\nvehicles, and customer notifications"]

    customer  -->|"Approves/rejects budget\nvia REST API"| system
    attendant -->|"Opens OS, records delivery\nvia REST API"| system
    mechanic  -->|"Diagnoses, adds items/services,\nexecutes via REST API"| system
    admin     -->|"Manages catalogue and users\nvia REST API"| system
```

## Level 2 — Container

How the system is deployed and how its main containers communicate.

```mermaid
flowchart TD
    subgraph github["GitHub"]
        ci["CI Workflow\n[GitHub Actions]\nBuild · Lint · Test"]
        cd["CD Workflow\n[GitHub Actions]\nDeploy via Terraform + kubectl"]
        ci -->|"on success → triggers"| cd
    end

    subgraph minikube["Local Kubernetes (Minikube)"]
        api["Car Repair Shop API\n[Node.js / Express]\nExposes REST endpoints;\nimplements Clean Architecture"]
        mongo["MongoDB\n[StatefulSet]\nPersists all domain data"]
        api -->|"Mongoose ODM\nport 27017"| mongo
    end

    subgraph infra["Terraform (infra/)"]
        tf["Terraform\n[IaC]\nApplies K8s manifests via\ngavinbunney/kubectl provider"]
    end

    cd -->|"terraform apply"| tf
    tf -->|"kubectl_manifest resources"| minikube

    user["Client\n[Browser / Postman]"]
    user -->|"HTTPS / NodePort"| api
```

## Level 3 — Component

Internal structure of the Car Repair Shop API following Clean Architecture.

```mermaid
flowchart TD
    subgraph layer4["Layer 4 — Frameworks & Drivers"]
        express["Express App\n(app.ts / main.ts)"]
        routes["Route files\n(authRoutes, serviceOrderRoutes, …)"]
        mongoose["Mongoose\n(database connection)"]
        express --> routes
    end

    subgraph layer3["Layer 3 — Interface Adapters"]
        controllers["Controllers\n(AuthController, ServiceOrderController, …)"]
        gateways["Gateways / Repositories\n(MongoServiceOrderRepository, …)"]
        services["Services\n(ConsoleNotificationService)"]
        routes --> controllers
    end

    subgraph layer2["Layer 2 — Use Cases"]
        usecases["Use Case classes\n(CreateServiceOrderUseCase,\nApproveBudgetUseCase, …)"]
        ports["Ports / Interfaces\n(IServiceOrderRepository,\nINotificationService, …)"]
        controllers --> usecases
        usecases -->|"depends on"| ports
    end

    subgraph layer1["Layer 1 — Entities"]
        entities["Domain Entities\n(ServiceOrder, Item, Customer, …)"]
        statemachine["State Machine\n(serviceOrderStateMachine)"]
        validators["Validators"]
        usecases --> entities
    end

    gateways -->|"implements"| ports
    services -->|"implements"| ports
    gateways --> mongoose
```
